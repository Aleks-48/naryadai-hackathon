# EnbekPlus v2: создание наряда мастером + RU / KK / EN, темы, фото, Telegram

## Важно перед установкой

Это подготовленное обновление исходников существующего Flutter-приложения. Исправление Content-Length, после которого вход мастера и исполнителя заработал на телефоне, сохранено. Новая версия ещё НЕ собрана и НЕ проверена Flutter-тестами на устройстве: в доступном окружении нет Flutter/Dart SDK. Код использует Flutter 3.35+. Присланный lockfile проекта требует Flutter 3.38+ / Dart 3.10+, поэтому используйте ваш текущий SDK и не понижайте его.

## Установка в текущий mobile_flutter

1. Сделайте копию текущей папки `lib` и `pubspec.yaml`
2. Скопируйте папки `lib`, `test` и `tool` из архива в `mobile_flutter` с заменой совпадающих файлов. Не удаляйте остальные файлы проекта
3. Замените `mobile_flutter/pubspec.yaml` файлом `pubspec.yaml` из архива и выполните `flutter pub get`. Он подготовлен из вашего загруженного pubspec: имя, описание, version, Dart SDK, image_picker, flutter_test и остальные настройки сохранены. Добавлены только flutter_localizations (Flutter SDK) и shared_preferences ^2.3.0

Если вы уже изменили pubspec после загрузки, вместо замены добавьте две зависимости командами:

```sh
flutter pub add 'flutter_localizations:{sdk: flutter}'
flutter pub add shared_preferences
flutter pub get
```

Код использует SharedPreferencesAsync (shared_preferences 2.3.0+). Код использует Flutter 3.35+. Присланный lockfile проекта требует Flutter 3.38+ / Dart 3.10+, поэтому используйте ваш текущий SDK и не понижайте его. Это обновление существующего проекта, а не полный Flutter scaffold: каталоги android/ios и текущий backend в архив не включены.

4. Проверьте и запустите приложение:

```sh
dart format lib test tool

flutter test test/create_order_test.dart test/master_entry_test.dart test/master_photo_actions_test.dart test/app_settings_test.dart test/translations_test.dart test/dropdown_initial_value_test.dart test/order_flow_regression_test.dart test/narrow_layout_test.dart test/order_photos_test.dart test/telegram_settings_test.dart

flutter run
```

После добавления shared_preferences нужен полный перезапуск/пересборка приложения, а не только hot reload. Если тесты/анализ выявят ошибку, сохраните их точный вывод и не объявляйте сборку готовой. Прежний рабочий APK и резервная копия позволяют вернуться к проверенной версии.

## Создать наряд мастером

Войдите как мастер → «Наряды» → «Выдать наряд». Заполните название/описание, выберите плановый или внеплановый тип, один из четырёх приоритетов, участок и его оборудование, исполнителя либо бригаду. Срок задаётся количеством часов (больше 0, не больше 720) или местной датой/временем; дата отправляется в UTC. Комментарий при выдаче необязателен.

Можно выбрать до пяти фото «до» через камеру/галерею. Фото необязательны. Используется существующий POST /api/orders: сначала один раз создаётся наряд, затем отдельными запросами отправляются фотографии. Это НЕ общая атомарная операция. Если часть фото не загрузилась, наряд уже существует: форма сохраняет его номер и предлагает повторить только подтверждённо неудавшиеся/ещё не отправленные загрузки либо открыть созданный наряд. В карточке мастера можно добавить фото «до», пока статус «Выдан» или «В очереди» и не достигнут лимит пять.

При потере ответа создания форма не отправляет второй POST: требуется вернуться к списку и проверить, появился ли наряд. При неопределённом результате загрузки фото доступна проверка уже сохранённых файлов; отсутствие фото в ответе проверки не запускает повторную отправку автоматически. Повторное нажатие и Back во время запроса блокируются. Рабочий и руководитель не получают кнопки создания; сервер проверяет роль независимо от клиента.

Эта совместимая последовательность выбрана осознанно: переданный web-клиент использует массив before_photos, а проверенный reference-backend принимает при создании только before_photo. Оба уже имеют отдельный endpoint фото. Новые endpoint и изменения backend не придуманы.

Прежний архив интерфейса v1 сохранён отдельно; этот архив v2 включает все прежние файлы интерфейса и добавляет создание. Теперь в lib восемь файлов.

## Что изменено

- Переключение RU / KK / EN на экране входа и в профиле, включая стандартные Material/Cupertino-подписи
- 445 переводимых строк: интерфейс, статусы, роли, диалоги, проверки полей, известные ошибки API, фото и Telegram
- Темы «Светлая», «Тёмная», «Как в системе» со спокойной зелёно-синей палитрой. Выбранные язык и тема сохраняются локально; логины, пароли, сессии и Telegram-коды туда не записываются
- Названия оборудования, имена, описания, комментарии и другие данные нарядов не переводятся автоматически
- Корректная подпись счётчика: «Активных нарядов: N»
- Защищённые миниатюры фото и открытие на весь экран с масштабированием двумя пальцами. Загрузка идёт только через существующий /api/photos/{id}, с текущей сессией. Внешние URL и перенаправления не используются
- В профиле — существующая привязка уведомлений Telegram: статус, явное подтверждение создания одноразового кода, срок действия, ручное обновление статуса и подтверждаемая отвязка. Переход Профиль ↔ Наряды не уничтожает ещё действующий код
- Ошибки действий больше не стираются последующим обновлением, список обновляется после возвращения из наряда, поздние ответы не вызывают setState после закрытия деталей
- Известные предупреждения main.dart: пять value → initialValue, удалён неиспользуемый helper подтверждения. Действующее подтверждение окончательной приёмки сохранено

## Как добавить и посмотреть фото

Исполнитель: выберите «Активные», откройте наряд. Для принятого наряда нажмите «Начать работу». В состоянии «В работе» или «Приостановлен» доступны «Снять фото» / «Из галереи». Существующий native-клиент загружает фото «после работ». Мастер может добавить фото «до» в карточке выданного/поставленного в очередь наряда. В закрытом наряде доступен просмотр. Нажмите миниатюру или значок разворачивания, чтобы открыть фото; при ошибке доступна повторная загрузка.

Фото не делаются публичными. Временные изображения держатся в памяти и удаляются из кэша при уходе/смене клиента. Ошибки 401/403/404, таймаут, неверный MIME/сигнатура и чрезмерный размер показываются отдельно. Интерфейс не выдаёт фотографии за подтверждение исправности оборудования.

## Роли и Telegram

Существующие роли сохранены: мастер, исполнитель, руководитель. Руководитель видит наряды без кнопок изменения; права на сервере не меняются. Создание наряда теперь доступно мастеру. Отдельная агрегированная панель отчётов руководителя в этом обновлении не добавлена.

Если backend сообщает, что Telegram отключён, приложение показывает это честно. Токен бота и webhook настраиваются на сервере; секреты в приложение не вводятся. При включённом Telegram пользователь подтверждает получение кода, вручную отправляет возвращённую команду своему настроенному боту в личном чате, затем обновляет статус. Разработчик этого архива не создавал и не активировал реальные коды.

Регистрация новых сотрудников и вход в приложение по Telegram OTP — отдельное изменение backend, НЕ реализованное здесь. Существующие /api/telegram/pair и /unpair относятся к привязке чата после входа, а не к регистрации или аутентификации. Для следующего этапа нужны текущий server.py, схема/миграции пользователей, тесты авторизации и несекретный пример настроек. Не присылайте bot token, пароли или .env с секретами.
