# EnbekPlus Mobile · Flutter v3

Нативный Flutter-клиент к Python HTTP API EnbekPlus. Текущая поставка содержит mobile v3, двухфайловый analyzer hotfix и исправление синтетической фикстуры HTTP-контрактного теста от 8 октября 2026. Backend находится в корне репозитория; общие запуск, аккаунты, интеграции и ограничения описаны в [главном README](../README.md).

## Точный статус

- Android scaffold сохранён в `android/`; iOS scaffold отсутствует
- Пользователь собрал APK: на предоставленном подтверждении виден успешный `Built` в 03:40 UTC 8 октября 2026; в 03:58 UTC он сообщил, что вход и фото работают
- Бинарник APK в эту поставку не передан и не опубликован; его SHA-256 и соответствие текущему Git-коммиту не подтверждены
- Успешная пользовательская сборка не равна свежей проверке финального v3 + hotfix. Полный `flutter analyze` и `flutter test` для этого дерева не подтверждены
- `gradle-wrapper.jar` отсутствует. Пакет его не генерирует, не скачивает и не передаёт
- Старый `pubspec.lock` сохранён, но не подтверждён после разрешения текущих зависимостей. Чистый clone пока не является воспроизводимой Android-сборкой
- Production backend/контейнеры этим обновлением не менялись. GitHub не выполняет deployment

## Возможности

- Вход по учётной записи и адресу существующего API; серверное разграничение ролей мастера, исполнителя и руководителя
- Список/детали нарядов и допустимые для роли действия; создание наряда мастером
- Фото из камеры/галереи, загрузка и просмотр защищённых фото по API
- Выбор RU/KK/EN, светлой/тёмной/системной темы; сохранение настроек языка и темы
- Настройки необязательной Telegram-привязки к уже настроенному серверному адаптеру
- Сохранённый результат проверки: режим, вывод, замечания, необходимость решения мастера, отдельные проверки фото и материалов
- Оценка текста отчёта `report_score`, обоснование и уверенность отдельно от финальных `rating` / `rating_reason` мастера
- Пометка предыдущего анализа после доработки/повторной сдачи; итоговая оценка закрытого наряда видна и без результата анализа

`rules-only` означает локальную проверку правил. Совпадающие серверные метки модели означают только сохранённый серверный результат, а не подтверждённый живой запрос. Фото/EXIF не доказывают свежесть съёмки или качество ремонта. Финальное решение остаётся за мастером.

Интерфейс и известные стандартные ошибки переведены; произвольные тексты наряда, модели и комментариев остаются на исходном языке. Клиент не вызывает сервис перевода. Полное совпадение функций с PWA/Streamlit не заявляется: расширенная отчётность и управление очередями описаны в главном README.

## Состав

```text
lib/main.dart               приложение, вход и ролевой интерфейс
lib/api.dart                HTTP, сессия/CSRF, Content-Length, защищённые фото
lib/create_order.dart       выдача наряда
lib/order_photos.dart       фото
lib/app_settings.dart       язык, тема и настройки
lib/translations.dart       RU/KK/EN
lib/telegram_settings.dart  привязка/отвязка Telegram через API
lib/ai_review.dart          ограниченный разбор сохранённого анализа
lib/ai_review_card.dart     информационная карточка анализа и оценки
test/                      Flutter/Dart тесты и синтетические fixtures
tool/                      статические проверки и регрессионные сценарии
android/                   сохранённый Android scaffold, без wrapper JAR
pubspec.yaml               зависимости и параметры Flutter-пакета
pubspec.lock               сохранённый исторический lockfile
```

Сессия и CSRF-токен живут только в памяти HTTP-клиента. Фотографии читаются по идентификатору через защищённый endpoint; перенаправления с cookie запрещены. Никакие API-ключи LLM или токены Telegram в клиент добавлять не нужно: эти интеграции настраиваются только на сервере.

## Перед проверкой и сборкой

1. Используйте Flutter **3.38+ / Dart 3.10+** с совместимыми Android SDK/JDK. Формальный нижний предел Dart в `pubspec.yaml` не доказывает совместимость старого SDK с используемыми пакетами и API
2. Нужен полный Android-проект в собственной доверенной среде с доступным Gradle wrapper. `gradle-wrapper.jar` отсутствует в этой поставке; команды ниже не устраняют этот блокер
3. Разрешите зависимости и проверьте обновлённый `pubspec.lock`. Сохранённый lock нельзя считать актуальным только потому, что файл есть в Git
4. Убедитесь, что используются одновременно v3 и hotfix-файлы `test/ai_review_card_test.dart`, `tool/ai_review_regression.dart`
5. Для API-сценариев используйте отдельную синтетическую базу и выключенные внешние интеграции. Не используйте рабочие секреты

Не запускайте повторное создание платформ поверх собственного проекта без проверки изменений: это может перезаписать Android-настройки. iOS-проект и его права камеры/фото нужно готовить отдельно; iOS-сборка не входит в результат.

## Команды проверки

Это инструкции для подготовленной среды, а не заявленные результаты выполнения. Из каталога `mobile_flutter`:

```sh
flutter --version
flutter doctor -v
flutter pub get
dart format --output=none --set-exit-if-changed lib test tool
flutter analyze
flutter test
dart tool/ai_review_regression.dart
dart run tool/api_transport_regression.dart
dart run tool/api_photo_regression.dart
```

Статические Python-проверки исходников можно выполнить отдельно:

```sh
python tool/verify_source.py
python tool/verify_review_source.py --backend ../server.py
```

Без `--baseline` второй скрипт не сравнивает полное дерево с исходной v2. При подготовке публикации статическая проверка переводов и `tool/check_create_contract.py` пройдены. В контрактном скрипте исправлена только фотофикстура: независимые детерминированные текстуры позволяют принять пять фото «до» и отклонить шестое уникальное с 400; раньше похожие изображения давали 409. Продуктовый детектор дублей не менялся. Эта проверка обращается к локальному HTTP API, не исполняет Dart. Статические проверки строк/контрактов не заменяют Dart parser, analyzer, Flutter-тесты или устройство. При ошибке форматирования внесите форматирование осознанно, проверьте diff и повторите анализ/тесты.

После устранения всех prerequisite-блокеров и успешных проверок:

```sh
flutter run
flutter build apk --debug
```

Обычный путь результата успешной debug-сборки — `build/app/outputs/flutter-apk/app-debug.apk`. Это ожидаемый путь, не готовое вложение. Release-подпись и публикация в магазине не настроены/не подтверждены.

## Адрес API и демо-вход

Сначала запустите backend по [главной инструкции](../README.md). По умолчанию он слушает `127.0.0.1:8765` на компьютере.

- Android-эмулятор на том же хосте: в поле адреса введите `http://10.0.2.2:8765`
- Исходный пример в клиенте — `http://10.0.2.2:8768`; он подходит только для API, действительно запущенного на 8768
- `localhost` / `127.0.0.1` на телефоне указывают на телефон. Loopback-порт Docker-хоста автоматически ему недоступен
- Для телефона нужен отдельно согласованный доступный серверный адрес, предпочтительно HTTPS. Не отключайте защиту сети и не выставляйте демо-API наружу для обхода ошибки входа

В локальном синтетическом seed: `master01`, `master02`, `worker01`–`worker15`, `manager`; общий учебный пароль — `demo123`. Это известные демо-реквизиты, непригодные для production.

Если вход не работает, сначала сравните адрес/порт и доступность `/api/health` из нужной среды. Сервер не должен требовать входа на этот маршрут. Убедитесь, что запрос действительно попадает в EnbekPlus API, а не в Streamlit-порт 8501 или промежуточную страницу.

## Что важно проверить на устройстве

- Вход каждой роли, выход, истечение сессии и повторный вход
- Создание мастером; принять/начать/пауза/возобновить/выполнить; доработка и окончательное закрытие
- Камера/галерея, отказ в разрешении, защищённый просмотр, дубли, лимит фото, повторная загрузка после доработки
- Потеря сети и восстановление без фиктивного успешного действия
- Старый/повреждённый анализ, честный `rules-only`, независимая итоговая оценка мастера
- RU/KK/EN, обе темы, узкий экран и увеличенный текст

Включённые тесты покрывают эти и другие случаи на уровне исходников/тестовых сценариев, но наличие теста не означает его успешное выполнение. Работа реальной LLM и Telegram требует отдельной серверной настройки и проверки.
