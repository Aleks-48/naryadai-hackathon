Android-проект использует Java 17, AGP 8.9.1, Kotlin 2.1.0 и Gradle 8.14. `minSdk` берётся из `flutter.minSdkVersion`; понижение SDK здесь не выполнялось. Android SDK и Flutter должны быть установлены и доступны обычной пользовательской сессии.

Его надо пересоздать через `flutter pub get`, проверить изменения и сохранить реально разрешённый результат. Хеши и версии вручную не подставлялись.

## Сборка и проверка

Из папки `mobile_flutter`:

```sh
flutter --version
flutter pub get
dart format lib test tool
flutter analyze
flutter test
dart run tool/api_transport_regression.dart
dart run tool/api_photo_regression.dart
flutter build apk --debug
```

Команды приведены для воспроизведения. Пользовательский Flutter-test прогон подтверждён отдельно (105 тестов); полная цепочка analyzer/build/install и GitHub CI не подтверждена одним этим логом. После изменения зависимостей нужна полная пересборка, а не hot reload. Flutter tooling должен заново сформировать plugin registrant и машинные SDK-настройки; не копируйте их с чужого ПК и не вписывайте классы plugin вручную.

После успешной debug-сборки ожидаемый файл: `build/app/outputs/flutter-apk/app-debug.apk`. Сначала сохраните прежний рабочий APK, затем проверьте установку, вход, темы/языки, роли, фото и ошибки сети на настоящем устройстве. Регистрация сотрудников и Telegram OTP-вход в этот пакет не входят: Telegram здесь привязывает уведомления после обычного входа.

Корневой `server.py`, PWA в `static/` и существующие серверные тесты репозитория сохранены. Они относятся к прежнему r3 этапу. Окончательный объединённый серверный снимок, используемый для нового мобильного клиента, в это обновление не включён.

Наличие исходников Flutter в репозитории не подтверждает совместимость всех новых экранов с корневым старым backend. Перед показом нужно отдельно сверить API-контракт и проверить новый APK с тем сервером, который будет использоваться на защите. Не затирайте более свежие серверные изменения старой копией.

## Только демонстрационная Android-конфигурация

В присланном scaffold сохранены `android:usesCleartextTraffic="true"` и подпись release-конфигурации debug-ключом. Они не расширялись в ходе этого обновления. Такая конфигурация не является production/Store-релизом. Для промышленного релиза отдельно нужны HTTPS-политика, безопасная подпись, серверные аккаунты и согласованная обработка данных.

Не добавляйте signing keys, пароли, `.env`, bot token или API key в Git. Тестируйте на синтетических данных. Фото и результат правил/LLM не подтверждают исправность оборудования и не заменяют решение ответственного мастера или наряд-допуск.
