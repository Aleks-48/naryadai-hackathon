# НарядAI

Локальный MVP для Qostanai AI Industry Hackathon 2026, кейс №1. Стек: Python 3.12, SQLite, HTTP API, адаптивная PWA и Pillow для безопасного декодирования изображений, EXIF и поиска похожих файлов.

## Запуск

Откройте PowerShell в папке проекта и выполните:

```powershell
.\start.ps1
```

Для отдельной установки Python-зависимостей: `python -m pip install -r requirements.txt`. Предоставленное рабочее окружение уже содержит Pillow.

Если политика PowerShell блокирует скрипт:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Либо запустите напрямую:

```powershell
& 'C:\Users\777\Documents\Codex\2026-09-30\task-2\.venv\Scripts\python.exe' .\server.py
```

Откройте `http://127.0.0.1:8765`. Первый запуск автоматически создаёт SQLite, каталог фотографий и 550 синтетических нарядов. По умолчанию они находятся в `data/`; переменная `NARYADAI_DATA_DIR` задаёт постоянный каталог. Остановка — `Ctrl+C`.

| Роль | Логин | Пароль |

| Исполнитель 1–15 | `worker01` … `worker15` | `demo123` |

Данные хранятся локально. Справочники: 4 участка, 25 единиц оборудования, 20 кодов неисправностей, 40 материалов; тестовая команда — 2 мастера, 15 исполнителей, 3 бригады. История построена детерминированно из четырёх демонстрационных паттернов. Имена вымышлены. Производственные сведения и реальные списки сотрудников не импортировались.

## Режимы ИИ и интеграции

- Без настроенных endpoint, модели и ключа текстовая проверка честно помечается `rules-only`; это не считается полноценным ИИ-соответствием кейсу.
- Для OpenAI-совместимого сервиса адаптер читает только `NARYADAI_LLM_API_URL`, `NARYADAI_LLM_MODEL`, `NARYADAI_LLM_API_KEY` из явных переменных окружения. В проекте нет ключей и `.env`; по умолчанию внешние запросы не выполняются. Используйте только одобренную конфигурацию сервиса и не помещайте секрет в репозиторий.
- Базовый фотоконтроль проверяет тип/содержимое JPEG, PNG или WebP, лимит до 5 файлов на каждую фазу «до/после», размер до 4 МБ, SHA-256-дубли, фазу и время загрузки. EXIF извлекается отдельно, как описано ниже. Загрузка файла не доказывает свежесть съёмки или исправность оборудования.
- Извлекаются EXIF DateTimeOriginal/DateTimeDigitized и часовой пояс, если он записан. Без даты интерфейс показывает, что время съёмки неизвестно. Фото оценивается по проверяемости файла (1 — точный дубль, 2 — похожий дубль, 3 — уникальный файл без даты EXIF, 4 — уникальный файл с датой, 5 — уникальный файл с датой и часовым поясом). Низкий балл требует явного решения мастера. Дата EXIF с часовым поясом сравнивается с моментом исполнения: допустимое окно по умолчанию 60 минут, настройка NARYADAI_PHOTO_CAPTURE_WINDOW_MINUTES. Если нет проверяемой даты в окне, обязательно обоснованное решение мастера; это проверка согласованности, а не доказательство свежести. Эта шкала не измеряет качество ремонта: EXIF можно изменить, а фото не подтверждает свежесть или исправность.
- Похожесть вычисляется 64-битным dHash через Pillow с ограничением цветового профиля; порог — расстояние Хэмминга ≤6 и близкая средняя цветовая подпись. Это сигнал повторного использования, не доказательство; сильное кадрирование/поворот может обойти сравнение. PWA перед отправкой уменьшает фото до 1600 px и сжимает в JPEG; EXIF переносится при поддержке браузера. Сервер хранит перекодированную версию. Даже EXIF и время загрузки не доказывают свежесть съёмки.
- Мультимодальное сравнение «до/после» и оценка качества ремонта без модели не заявляются.
- События складываются в локальный `telegram_outbox` со статусом `queued_local`. Бот, токены, Telegram API и внешние сообщения не создавались. Обсуждавшийся выбор Telegram+Gemini пока ожидает ответа пользователя; внешние настройки не менялись. Реальный push на телефон остаётся незавершённой интеграцией и не засчитывается как выполненный критерий.
- Service worker кэширует только оболочку приложения. Офлайн-запись и синхронизация команд не реализованы. Для установки Android PWA нужен `localhost` или HTTPS; простой HTTP-доступ к ПК из локальной сети не даёт надёжного installable PWA.

## Ограничения и безопасность

Это локальный демонстрационный прототип, не производственная система. HTTP-сервер привязан к `127.0.0.1` по умолчанию; в нём нет TLS, интеграции с корпоративной учётной записью, управления администратором, регламента смен предприятия и утверждённых нормативов расхода/трудоёмкости. Не открывайте его в сеть предприятия и не загружайте непубличные производственные материалы.

НарядAI регистрирует ремонтную работу и не является нарядом-допуском. Он не выдаёт разрешение на опасную работу, не подтверждает безопасность, не заменяет инструктаж, внешние документы, подписи или решение ответственного лица. Описанный пользователем личный опыт подписания документов не подтверждён как регламент заказчика. Отказ или пауза из-за отсутствия допуска не штрафуется автоматически: необоснованность отказа может отметить только мастер с аудируемой причиной.

Сессии хранят хеш opaque-токена, пароль сверяется PBKDF2-HMAC-SHA256, изменяющие запросы требуют CSRF-токен, роль и область наряда проверяются на сервере. У менеджера только GET-доступ. Подробная [матрица требований](docs/requirements-and-scope.md) и [API для будущего Flutter-клиента](docs/api.md) описывают границы и права сервера.

- `static/` — PWA, мобильная вёрстка, панель мастера и экран исполнителя.

Исходные 11 Python-тестов пройдены в отдельной копии. Добавлены 14 независимых регрессионных тестов; итог 25/25. Проверки исполняют настоящий HTTP API с временной синтетической базой. Исправлены права прежнего исполнителя после переназначения, отзыв отключённых сессий, числовая валидация, лимиты фото по фазам, сравнение EXIF, повторная эскалация выдачи, атомарность таймеров, чтение уведомлений и учёт AI-доработок. При ручной связи рейтинг пересчитывается; причина и аудит хранят обе стороны записи. Отозванная связь больше не влияет на повторный фактор.

## Docker

`docker compose up --build` собирает API/PWA и хранит SQLite/фото в именованном volume `naryadai-data`; локальный порт привязан только к `127.0.0.1:8765`. Docker в этой рабочей сессии не запускался. `docker compose down` сохраняет данные; `docker compose down -v` удаляет volume с базой и фото. Переменные пусты, поэтому LLM остаётся в `rules-only`. Внешний HTTPS, push, публичный host и постоянный удалённый диск этим файлом не создаются.

Опциональный UI поверх того же API: `docker compose --profile demo-ui up --build` (Streamlit на `127.0.0.1:8501`). Каждый браузерный сеанс создаёт отдельную API-сессию; роли повторно проверяет `server.py`. Streamlit не содержит моков, базы или таймера. При перезапуске UI пользователь входит снова, а SQLite и фото остаются в volume API. Для прямого запуска: установите отдельный необязательный пакет из `requirements-streamlit.txt`, задайте `NARYADAI_API_URL` и запустите `streamlit run streamlit_app.py`. Пакет в текущем окружении не устанавливался.

Streamlit Cloud или иной внешний UI требует отдельно доступного HTTPS API с постоянным хранилищем; бесплатный host, его сон/перезапуск и сохранность SQLite здесь не подтверждались. Образ не делает деплой и не открывает порт наружу.
