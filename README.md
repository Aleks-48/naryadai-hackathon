## Что решает проект

EnbekPlus объединяет выдачу ремонтного задания, ход выполнения, фото, расход материалов, проверку отчёта и приёмку мастером. История действий и причины решений сохраняются в аудите. Руководитель видит общую картину работ, просрочки, нагрузку и отчётность.

Это демонстрационный MVP на синтетических данных. Он регистрирует ремонтную работу, но не является нарядом-допуском, не подтверждает исправность оборудования и не разрешает опасные работы.

## Сайт и приложение

| Компонент | Что доступно |
|---|---|
| Сайт / PWA | Адаптивный браузерный интерфейс, доска нарядов, фильтры, отчёты, ручная очередь работ, регистрация простоя и ролевые действия |
| Flutter / Android | Вход по адресу API, список и детали нарядов, создание мастером, действия по ролям, камера/галерея, защищённые фото, сохранённый анализ и окончательная оценка |
| Настройки мобильного клиента | RU / KK / EN; светлая, тёмная и системная тема; сохранение выбранных настроек |
| Streamlit | Дополнительный демонстрационный интерфейс поверх того же API |
| Python API | SQLite, сессии, CSRF, серверные права, статусы, аудит, фото, очереди и опциональные внешние интеграции |

Произвольный текст наряда, отчёта модели и комментария мастера остаётся на исходном языке. Внешний переводчик не вызывается. Полное совпадение всех экранов PWA, Streamlit и Flutter не заявляется.

### Роли

- **Мастер:** выдаёт плановые и внеплановые наряды, выбирает исполнителя или бригаду, задаёт приоритет и срок, переназначает допустимые наряды, проверяет результат, возвращает на доработку и закрывает с комментарием и оценкой
- **Исполнитель:** видит свои назначения, принимает или отклоняет с причиной, начинает работу, ставит на паузу, возобновляет и сдаёт отчёт с часами, материалами и фото
- **Руководитель:** читает общие наряды, отчёты, рейтинг и аудит; не меняет наряды и не выполняет приёмку

Основной путь: `issued → accepted → in_progress → executed → ai_review → closed`. Дополнительно предусмотрены очередь, отказ, пауза и доработка. Права и допустимые переходы проверяются сервером, а не только видимостью кнопок.

### Фото, материалы и отчёты

- Фото «до» необязательно. Для каждой фазы допускается до пяти активных JPEG / PNG / WebP, до 4 МБ на файл
- Точные и похожие дубли отклоняются. После возврата на доработку прежние фото «после» становятся неактивными; история сохраняется
- EXIF и похожесть дают проверяемые признаки файла. Они не доказывают свежесть съёмки, качество ремонта или безопасность машины
- Отсутствие строк материалов означает неизвестный расход. Нулевой расход подтверждается отдельной отметкой; конфликт отметки и материалов не превращается в корректный ноль
- Учебные ориентиры расхода и часов явно помечены как синтетические; это не нормативы предприятия и не основание автоматических кадровых решений
- Простой оборудования регистрируется вручную закрытым интервалом UTC с причиной. Перекрытия объединяются по оборудованию; паузы работника и фактические трудозатраты учитываются отдельно
- Ручная очередь исполнителя/бригады не меняет приоритет, срок или назначение. Версия очереди защищает от устаревших перестановок

## Быстрый запуск актуальной версии

Нужны Git, Python 3.12 и доступ к установке зависимостей. Сначала получите **нужную ветку**, а не стандартный clone `main`:

```sh
git clone --branch enbekplus-mobile-source-20261007 --single-branch https://github.com/Aleks-48/naryadai-hackathon.git
cd naryadai-hackathon
git rev-parse HEAD
```

При проверке опубликованного снимка ожидаемый HEAD — `0a7a2a035e7a05de75dd02d1818009e3cc672995`. Если ветка обновилась, этот commit можно проверить отдельно командой `git checkout 0a7a2a035e7a05de75dd02d1818009e3cc672995`.

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-api.txt
.\.venv\Scripts\python.exe server.py
```

### Linux / macOS

```sh
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-api.txt
python server.py
```

Откройте сайт: **http://127.0.0.1:8765**. Проверка API: **http://127.0.0.1:8765/api/health**. Остановка — `Ctrl+C`. Для другого локального порта: `python server.py --port 8768`.

При первом запуске создаются SQLite, каталог фото и 550 синтетических нарядов. Каталог данных по умолчанию — `data/`, переопределение — `NARYADAI_DATA_DIR`. В демо: 4 участка, 25 единиц оборудования, 20 кодов неисправностей, 40 материалов, 2 мастера, 15 исполнителей и 3 бригады. Реальные сотрудники и производственные сведения не импортировались.

### Docker и Streamlit

```sh
docker compose up -d --build app
```

API/PWA доступны на `127.0.0.1:8765`, данные сохраняются в именованном томе `naryadai-data`. Опциональный Streamlit:

```sh
docker compose --profile demo-ui up -d --build
```

Его адрес — `http://127.0.0.1:8501`. Без Docker: установите `requirements-streamlit.txt` и выполните `python -m streamlit run streamlit_app.py`.

При обновлении сохраняйте существующий Compose-проект, `.env` и том. **Не используйте `docker compose down -v`: команда удаляет том с базой и фото.** Публикация кода на GitHub не обновляет работающий сервер; существующий Docker-экземпляр этим документационным обновлением не развёртывался.

В embedded-режиме Streamlit запускает отдельный loopback backend и намеренно отключает внешние LLM/Telegram. Облачный эфемерный хостинг может сбрасывать SQLite и фото; такие варианты пригодны только для синтетического демо и не считаются проверенным production-развёртыванием.

## Что означает ИИ в проекте

- **По умолчанию `rules-only`:** локальные правила проверяют полноту отчёта, материалы, фото и условия приёмки. Смысловая проверка реальной моделью в этом режиме не выполняется
- Внешняя текстовая LLM опциональна. Требуются явный `NARYADAI_LLM_ENABLED=1`, модель и ключ; одного наличия ключа недостаточно. При недоступной конфигурации или ошибке сервер сохраняет явно обозначенный fallback
- LLM получает текст отчёта и ограниченный контекст наряда. Встроенное скрытие некоторых очевидных секретов не гарантирует анонимность произвольного текста; для демо используйте только синтетические данные
- Сводка отчёта включается отдельно через `NARYADAI_LLM_REPORT_SUMMARY=1` и явное действие. Она передаёт ограниченные агрегаты при достаточном числе записей
- Flutter v3 показывает сохранённый режим, вывод, замечания, оценку текста и уверенность отдельно от итоговой оценки мастера. Предыдущий анализ после доработки помечается как предыдущий
- Реальный вызов LLM и его качество для опубликованного снимка не подтверждены. Окончательное решение принимает мастер; мультимодальная оценка качества ремонта не заявляется

Telegram также **выключен по умолчанию**. Для адаптера нужны флаг включения, токен бота, webhook secret, доступный HTTPS webhook и отдельная привязка личного чата. Очередь и fake sender проверены; реальная доставка для актуального снимка не подтверждена. Секреты храните локально, не добавляйте в Git, APK, ZIP или скриншоты. Безопасный шаблон находится в `.env.example` актуальной ветки.

Service worker кэширует оболочку PWA. Офлайн-запись и синхронизация команд не реализованы. Установка PWA требует подходящего HTTPS/localhost-контекста и отдельно проверяется на целевом устройстве.

## Сценарий демонстрации

1. Мастером создайте внеплановый наряд для `worker01`; фото «до» можно пропустить
2. Исполнителем примите задание, начните работу, заполните отчёт, часы, код неисправности и материалы
3. Покажите `rules-only`: отсутствие фото «после» требует доработки
4. Добавьте допустимое синтетическое фото, повторно сдайте результат, затем мастером проверьте и закройте с комментарием
5. Покажите анализ отдельно от окончательной оценки, аудит, отчётность и read-only доступ руководителя

## Безопасность и границы MVP

Сервер использует хеши opaque-сессий, PBKDF2 для паролей, CSRF и проверки роли/области наряда. При этом проект не содержит полноценного корпоративного администрирования, SSO, TLS-терминации, утверждённых нормативов и регламентов предприятия. Демо-пароли известны. Для промышленной эксплуатации нужны отдельные проектирование защиты, резервное копирование, эксплуатационные процедуры и проверка интеграций.

Не загружайте реальные производственные или персональные данные. Рейтинг, фото, EXIF, LLM и ручной учёт времени не заменяют ответственного специалиста и требования промышленной безопасности.
