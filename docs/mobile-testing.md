# Мобильная проверка и локальное демо

Это инструкция для проверенного исходного снимка r3 от 6 октября 2026 года. В репозитории он опубликован коммитом `a679188baac120213a4cb3ab3285aea59a48a1e3`. Руководство разделяет проверку интерфейса на ПК, запуск на настоящем Android и будущую APK-сборку.

Выбрано новое название **EnbekPlus**. Текущий проверенный снимок r3 ещё показывает «НарядКонтроль»; интерфейс будет переименован в отдельном выпуске.

## 1. Что можно проверить сейчас

| Вариант | Состояние |
|---|---|
| Адаптивный веб-интерфейс/PWA | Исходники есть в `static/`; работает через `server.py` |
| Узкий мобильный интерфейс на ПК | Подготовлен отдельный Docker-launcher для свежего синтетического демо |
| Установка PWA на Android | Требует доступного с телефона адреса и отдельной проверки на устройстве |
| Готовый APK | В этом снимке не собран; файла для установки Android-приложения нет |
| Streamlit | Дополнительный веб-интерфейс над тем же API; не Android-сборка |

На ПК можно проверить формы, роли, очередь и ремонтный цикл. Узкое окно браузера и Device Mode показывают приближение мобильного интерфейса; они не подтверждают работу Android, камеры, экранной клавиатуры и системных разрешений. [Ограничения Device Mode](https://developer.chrome.com/docs/devtools/device-mode#limitations)

## 2. Быстрый запуск на Windows: отдельное свежее демо r3

Используйте отдельный проверенный пакет `NaryadAI-Docker-Mobile-Launcher-QA-20261006-r1.zip`. Он содержит launcher, его тесты и точный исходный архив r3. Пакет запуска распространяется отдельно от исходников этой ветки.

SHA-256 пакета запуска:

```text
1f56fec83fd969fc78b081308e004f8d3ce7bd39f10d51ad53d3105b9c0e0418
```

Внутри пакета нужен неизменённый `deliverables/NaryadKontrol-source-20261006-r3.zip`:

```text
163dd2f059879ecfd77bf76445b6997457068842221b56cf33df21a77c0a9280
```

### Перед запуском

1. Распакуйте весь пакет, сохранив структуру папок. Исходный ZIP должен лежать рядом с `start-naryadai-demo-r3.ps1`.
2. Нужны Windows, PowerShell 7 (`pwsh`) и запущенный локальный Docker Engine, способный собирать Linux-образ проекта. Для первой сборки может потребоваться интернет для образа Python и зависимостей.
3. Edge используется для автоматического открытия отдельного окна. Если Edge не найден, launcher выведет адрес для ручного открытия.

Из корня распакованного пакета:

```powershell
pwsh -NoProfile -File .\deliverables\start-naryadai-demo-r3.ps1
```

Запускайте скрипт сами в обычной рабочей сессии. Если действующая политика компьютера запрещает выполнение, не отключайте её ради демо: выясните допустимый способ запуска у владельца компьютера.

### Что делает launcher

- Проверяет SHA-256 исходного r3 ZIP до сборки.
- Принимает только локальный Windows Docker endpoint; неизвестный или удалённый endpoint отклоняет.
- Выбирает свободный порт в диапазоне `8768–8799`, привязанный только к `127.0.0.1`.
- Создаёт отдельный контейнер и новый именованный volume с уникальным суффиксом. Существующая база и старые сервисы не используются.
- Запускает API/PWA с синтетическими данными; LLM и Telegram явно выключены.
- Проверяет точный ответ `/api/health` для r3, затем открывает Edge с новым временным профилем и окном `412×915`. Размер окна не равен гарантированному размеру viewport.
- Выводит фактический URL, имя контейнера и имя нового volume. Используйте именно этот URL, а не адрес старого демо.

Свежий запуск создаёт новый набор демоданных. Не рассчитывайте найти в нём наряды, созданные в предыдущем запуске. Данные уже созданного volume не удаляются автоматически. Закрытие окна Edge не останавливает контейнер.

Для остановки найдите в Docker Desktop контейнер с точным именем, которое напечатал launcher. Не останавливайте чужие контейнеры и не удаляйте volume, если хотите сохранить результаты проверки.

**Граница проверки:** launcher прошёл тест с fake Docker и разбор PowerShell-скриптов. В этом подтверждённом результате нет реальной сборки образа, запущенного Docker-контейнера или Android-теста. Успешный живой запуск нужно подтвердить отдельно по выводу launcher и открывшейся странице.

6 октября 2026 года при ручном запуске сообщено об ошибке; причина пока не установлена, успешный живой Docker-запуск не подтверждён.

### Если запуск остановился

| Сообщение или симптом | Что проверить |
|---|---|
| Архив не найден | Сохранена ли структура пакета; лежит ли точный r3 ZIP рядом со скриптом |
| SHA-256 mismatch | Скачайте исходный проверенный пакет заново; не отключайте проверку хеша |
| Docker CLI не найден | Доступна ли установленная Docker CLI в вашей сессии |
| Engine access denied/unavailable | Запущен ли Docker Desktop и доступен ли локальный Engine этой пользовательской сессии |
| Remote or unknown endpoint | Launcher остановился до создания ресурсов; не переключайте его на удалённый сервер |
| Image build failed | Проверьте текст ошибки сборки. Launcher намеренно передаёт пустые proxy-параметры и не подбирает обходной proxy |
| Health did not pass | Контейнер мог быть создан. Проверьте его статус и логи по напечатанному имени; не считайте этот запуск успешным |
| Edge не открылся | Если health уже пройден, откройте URL из консоли в браузере |

Переименование продукта не обновляет этот пакет автоматически. Launcher r3 закрепляет старый архив и точное имя в health-ответе. Не подменяйте его ZIP, ожидаемый хеш или health-проверку вручную. Для следующей версии нужен отдельно проверенный пакет запуска.

## 3. Как смотреть мобильную вёрстку на ПК

1. Откройте URL свежего демо.
2. Начните с узкого окна, которое открыл launcher.
3. Для заданного viewport откройте инструменты разработчика браузера и включите Device Toolbar/режим устройства.
4. Проверьте ширины `360`, `390` и `412` CSS px, затем горизонтальную ориентацию.
5. Повторите ключевые действия при увеличенном масштабе текста. Проверьте, что кнопки, подписи, выпадающие списки и сообщения ошибок видны и доступны.

Устройство, ширина, масштаб и время выполнения сценария записываются по факту. Нормативы «выдать за минуту», задержка обновления и плавность на Android этим снимком не подтверждены. [Как пользоваться Device Mode](https://developer.chrome.com/docs/devtools/device-mode)

## 4. Как проверить на настоящем Android

`127.0.0.1` на телефоне указывает на сам телефон. Loopback-адрес launcher на ПК с телефона недоступен, даже если устройства находятся в одной Wi-Fi-сети.

Для отдельного Android-сеанса нужно:

1. Согласовать доступный с телефона HTTPS-адрес и условия доступа к синтетическому демо.
2. Открыть этот адрес в браузере Android и пройти сценарии из раздела 6.
3. Если браузер предлагает установку, проверить пункт установки/добавления на главный экран, повторный запуск и выход из аккаунта.

Ngrok или другой туннель требует отдельной настройки и разрешения на публикацию демо. Launcher не создаёт туннель, не меняет firewall и не открывает порт в локальную сеть. Демо-логины известны, поэтому публичный URL и доступ к нему нужно продумать до публикации. Используйте только синтетические данные.

Для установки PWA обычно нужен HTTPS; исключение для локальной разработки относится к `localhost`/`127.0.0.1` того устройства, где работает браузер. Обычный HTTP-адрес компьютера в сети не подтверждает installable PWA. [Условия установки PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)

Вариант установки зависит от устройства и браузера: возможны WebAPK или ярлык. Такая установка не создаёт проверенный распространяемый `.apk` проекта. Отдельной APK-сборки, подписи, установки и обновления APK в этом релизе нет. [Установка PWA на Android](https://web.dev/learn/pwa/installation)

Service worker проекта кэширует оболочку. Офлайн-изменение нарядов и последующая синхронизация не реализованы; для рабочих действий нужен доступ к API.

## 5. Демо-аккаунты и данные

Пароль всех перечисленных учебных аккаунтов: `demo123`.

- `master01`, `master02`: мастер выдаёт и переназначает наряды, управляет своей очередью, проверяет результат и принимает работу.
- `worker01`…`worker15`: исполнитель работает с доступными назначениями, пишет отчёт и загружает фото «после».
- `manager`: руководитель смотрит общую аналитику, без изменений нарядов.

Для параллельной проверки ролей используйте отдельные профили/сеансы браузера. Обычные вкладки одного профиля разделяют cookie и не гарантируют независимые аккаунты.

При первом запуске свежей базы ожидаются 550 синтетических нарядов, 4 участка, 25 единиц оборудования, 20 кодов неисправностей, 40 материалов, 2 мастера, 15 исполнителей и 3 бригады. Учебные нормы материалов и трудоёмкости не являются утверждёнными нормативами предприятия. Дедлайн заявки не равен трудовой норме.

## 6. Что пройти руками

### Основной ремонтный цикл

1. Войдите как `master01`, выдайте внеплановый наряд `worker01`. Фото «до» оставьте пустым: выдача и принятие должны быть доступны.
2. В отдельном сеансе войдите как `worker01`, примите наряд и начните работу.
3. Заполните текст выполненных работ, код неисправности, трудозатраты и материалы либо явную отметку «материалы не использовались». Отдельный комментарий исполнителя необязателен.
4. Для отрицательного сценария отправьте внеплановый отчёт без фото «после». При проверке должен быть результат «Доработка»; мастер не должен закрыть такой наряд без исправления.
5. Возобновите работу, загрузите допустимое синтетическое фото «после», исправьте отчёт и повторите проверку.
6. Вернитесь в роль мастера, прочитайте результат проверки и аудит. Закройте наряд только после необходимых исправлений и отдельного комментария мастера.

По умолчанию проверка выполняется в явно обозначенном `rules-only`. Наличие фото само по себе не гарантирует положительный результат или закрытие: остальные критерии и решение мастера остаются обязательными.

### Фото и ошибки ввода

- Повторите выдачу планового и внепланового наряда с `0`, `1` и `5` допустимыми фото «до». Фото «до» необязательно для обоих типов.
- Пока наряд «Выдан» или «Очередь», мастер может добавить фото «до» из карточки. Активных фото каждой фазы должно быть не больше пяти.
- Попытка шестого уникального фото должна отклоняться. Точный/похожий дубль должен отклоняться без создания дополнительного media-файла; причина остаётся в аудите.
- Проверяйте только синтетические JPEG/PNG/WebP. Серверный предел одного декодируемого файла составляет 4 МБ; клиентское сжатие не отменяет серверные проверки.
- После возврата на доработку ранее активные фото «после» перестают быть действующими; исполнитель загружает новое фото после начала доработки.
- Оставьте обязательную причину паузы/отказа пустой: действие должно быть отклонено. После заполнения проверьте причину в журнале.

Фото, EXIF и время загрузки не доказывают свежесть съёмки, качество ремонта, исправность оборудования или право на опасные работы.

### Очередь, роли и повторные действия

- Мастер меняет порядок активных задач своего исполнителя или бригады; приоритет, дедлайн и статус от этого не меняются.
- Исполнитель видит сохранённый порядок без права менять его. Руководитель остаётся в режиме чтения.
- В двух сеансах мастера измените одну очередь. Устаревшее изменение должно отклоняться и требовать обновления, а не перезаписывать свежую очередь.
- Проверьте повторные нажатия, закрытие окна формы, возврат назад, выход и повторный вход. Отмечайте фактический результат, особенно дубли нарядов, потерянные поля и перескоки состояния.
- Переназначьте наряд и проверьте, что прежний исполнитель теряет доступ к изменению чужой работы.

Короткий сценарий показа уже есть в [demo-script.md](demo-script.md). Точные маршруты, статусы и коды ошибок приведены в [api.md](api.md); покрытие требований и ограничения — в [requirements-and-scope.md](requirements-and-scope.md).

## 7. ИИ, Telegram и разные запущенные версии

В свежем launcher-демо внешние LLM и Telegram отключены. Тесты используют локальные fake-адаптеры; зелёный тест не подтверждает доставку настоящего сообщения или качество внешней модели.

Если на компьютере уже работает более старый сервер, бот или HTTPS-туннель, его состояние относится к тому отдельному процессу. Оно не подтверждает, что свежий r3 на новом порту подключён к тому же боту или модели. Сверяйте URL, порт, запущенную версию и режим интеграций; существующие процессы launcher не обновляет.

Подключение внешней LLM, Telegram webhook и отправка данных требуют отдельной согласованной настройки. Токены и ключи не добавляйте в репозиторий, скриншоты, команды для обсуждения или сообщения об ошибке. Streamlit embedded-режим намеренно отключает внешние интеграции.

## 8. Важное предупреждение перед обновлением существующей базы

**Перед первым запуском r3 на существующих данных нужна согласованная резервная копия SQLite и каталога фото/всего volume, а также понятный способ восстановления.** Для первой проверки используйте свежую синтетическую базу launcher.

В r3 старые дубли фото могут быть деактивированы при инициализации. При возврате на доработку прежние активные фото «после» заменяются в истории. Соответствующие media-файлы удаляются после успешного commit; метаданные и аудит сохраняются. Откат одного только кода не восстановит удалённые файлы.

Проверьте состав копии и восстановление отдельно до запуска на ценных данных. Публикация исходников в GitHub сама по себе не запускает эту миграцию. Не применяйте `docker compose down -v` к volume с нужной историей: команда удаляет данные.

## 9. Что подтверждено для r3

- Точный исходный архив: SHA-256 `163dd2f059879ecfd77bf76445b6997457068842221b56cf33df21a77c0a9280`.
- Независимый прогон: 75 Python-тестов, 32 Node-теста и 6 Streamlit AppTests прошли.
- Дополнительно проверены физические ограничения media-файлов, восстановление очистки, транзакционный откат и конкурентные загрузки.

Не подтверждены этим отчётом: APK, установка и работа на реальном Android, камера и системные разрешения телефона, замеры времени сценариев, внешняя LLM, Telegram-доставка текущего r3, production-размещение и восстановление реальной базы предприятия.

## 10. Как зафиксировать найденную проблему

Запишите версию/коммит, URL и порт демо без секретных параметров, устройство и браузер, роль, точные шаги, ожидаемый и фактический результат. Приложите скриншот на синтетических данных и время ошибки. Уточните, воспроизводится ли она в свежем профиле и после повторного входа.

Не прикладывайте cookie, CSRF-токены, ключи, реальные персональные или производственные сведения. Проект ведёт ремонтные наряды; он не выдаёт наряд-допуск и не подтверждает безопасность опасной работы.
